# Обход блокировок (VPN): журнал попыток

Сервер: VPS `85.209.155.32` (UFO.Hosting, Haedus, Финляндия).
Задача: один сервер, полный VPN для ПК (Windows) и телефонов, из РФ, без платных сервисов.
Период: 23–24 сентября 2026.

> Все пароли, приватные ключи, PSK, UUID и короткие ID здесь намеренно опущены.

## 1. AmneziaWG
- Развёрнут контейнер `amnezia-awg`, интерфейс `wg0`, UDP `51820`.
- Обфускация: junk-пакеты (Jc/Jmin/Jmax) + магические заголовки (S1/S2, H1–H4).
- NAT и FORWARD для подсети `10.8.1.0/24` настроены.
- В списке клиентов есть запись «Admin [Windows 11]»; с домашнего IP был успешный handshake, но трафик почти не пошёл.
- Клиентский конфиг для импорта в Amnezia подготовлен отдельно (не коммитится из-за ключей).

## 2. XRay VLESS + Reality
- Контейнер `amnezia-xray`, TCP 443, маскировка под нейтральный сайт.
- Из РФ: TCP-соединение открывается, но страницы не догружаются (классическое «душение» потока ТСПУ).
- Пробовали разные `dest` (samsung, icloud, yahoo, googletagmanager); часть целей не проходит handshake.

## 3. Shadowsocks-2022
- Контейнер `xray-ss`, TCP+UDP `8388`, метод `2022-blake3-aes-128-gcm`.
- Прямое подключение из РФ не работает.
- Использовался как внутренний backend для ShadowTLS.

## 4. Hysteria2
- UDP `443` (и альтернативный `20000`), obfs `salamander`, self-signed сертификат.
- Из РФ UDP-транспорт непригоден (шейпинг/блокировка).

## 5. MTProto (mtg)
- TCP `9443`. Работает только для Telegram, как общий VPN не подходит.

## 6. Cloudflare Worker (VLESS-over-WS)
- Собственный воркер на `*.workers.dev`; задеплоен через CF API.
- Из РФ `*.workers.dev` и `*.trycloudflare.com` глушатся по имени хоста.
- Domain fronting (SNI `www.cloudflare.com` + Host воркера) даёт HTTP 403.
- Бесплатный домен (DigitalPlat) не удалось получить: требуется KYC через GitHub, лимит 1 домен.
- Токен CF без права создавать зоны; зона осталась неактивной.

## 7. ShadowTLS v3 + Shadowsocks-2022
- Идея: клиент маскируется под обычный TLS к нейтральному сайту, сервер ретранслирует handshake.
- Сначала подняли Rust-сервер ShadowTLS — он оказался несовместим с sing-box-клиентом (`hmac mismatch`).
- Затем сервером сделали sing-box. С `strict_mode: true` связка ломается (баг парсинга TLS 1.3), с `strict_mode: false` — работает.
- Сервер исправлен на `strict_mode: false`; с внешнего канала проверено 12/12 (внешний IP + YouTube 200).
- У пользователя (Hiddify, ПК): статус «подключено», но сайты висят. По логам сервера подключения доходят, видны единичные сбои расшифровки SS и попытки IPv6 (у VPS нет IPv6).
- Диагностика продолжается (включён подробный лог сервера).

## Выводы
- Прямые протоколы (Reality, SS-2022, Hysteria2) из РФ непригодны — ТСПУ пропускает рукопожатие, но душит поток.
- CDN-обход через `*.workers.dev` не работает из-за блокировки по имени и отсутствия своего домена.
- Наиболее перспективны: AmneziaWG (обфускация WireGuard) и ShadowTLS v3 + SS-2022; оба требуют доведения до стабильного прохождения трафика.
