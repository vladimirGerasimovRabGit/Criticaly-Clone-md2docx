# mc-bridge — мост к браузеру в обход приложения

Полная памятка (диагноз, все доработки, инструкция для будущих версий) —
`../../AdditionalBridgeToClickandOther.md`.

## Зачем

В сборке MonkeyCode `26091601.0.0` сломан `browser_snapshot`: расширение отдаёт
разметку страницы строкой, а парсер приложения ждёт массив, поэтому ссылки на
элементы не регистрируются и `browser_click` / `browser_type` /
`browser_select_option` не работают ни на одной странице.

Расширение MonkeyCode при этом исправно — это тонкий релей над
`chrome.debugger`, который просто выполняет приходящие CDP-команды. В его
настройках можно указать любой порт, поэтому «локальным агентом» может стать
этот скрипт: он говорит на том же протоколе (`hello` → `hello.ok`, кадры с
`op`), а наружу отдаёт обычный HTTP-API для CDP.

## Запуск

```
python bridge.py            # порт 8791
```

Логи: `bridge.log` рядом со скриптом. Переменные окружения: `MCB_PORT`,
`MCB_TIMEOUT`, `MCB_TOKEN`, `MCB_LOG`.

## Как переключить на него расширение

1. В Edge открыть `edge://extensions` → «MonkeyCode 浏览器助手» → «扩展程序选项»
   (или сразу `chrome-extension://bhmoekbeakkmhaakojecgmnaomcepboa/src/options/options.html`).
2. Поле `agent 端口` = `8791`, `配对码` = любое слово → «连接并配对».

Обратно: очистить поле `agent 端口` (пусто = авто-сканирование 7440-7449) и
снова «连接并配对». Токен мост отдаёт тот же, что выдало приложение, поэтому
перепаривание не требуется. Важно: непустой порт фолбэка не имеет — если мост
не запущен, браузерные инструменты приложения останутся нерабочими, пока поле
не очистят.

## API (127.0.0.1:8791)

| Метод | Тело | Что делает |
|---|---|---|
| GET | `/status` | подключено ли расширение, сведения о нём |
| GET | `/tabs` | список вкладок с пометкой `controlled` |
| GET | `/testpage` | тестовая страница для самопроверки |
| POST | `/op` | произвольный кадр протокола, например `{"op":"tabs.create","params":{"url":"http://..."}}` |
| POST | `/cdp` | `{"method":"Runtime.evaluate","params":{...},"tabId":N}` |
| POST | `/eval` | `{"expression":"...","tabId":N}` → значение |
| POST | `/click` | `{"selector":"...","index":0,"count":2}` или `{"x":N,"y":N}`; `count` — двойной/тройной клик |
| POST | `/drag` | `{"x1":N,"y1":N,"x2":N,"y2":N}` — выделение протяжкой мышью |
| POST | `/select` | `{"selector":"...","index":0}` — выделить текст элемента |
| POST | `/edit` | `{"command":"copy"}` — `selectAll` / `copy` / `cut` / `paste` / `undo` / `redo` |
| POST | `/key` | `{"key":"Tab","modifiers":["ctrl"],"commands":["copy"]}` |
| POST | `/type` | `{"text":"..."}` — вставка текста (`Input.insertText`) |
| POST | `/shot` | `{"path":"C:/tmp/shot.png"}` |

`tabId` необязателен: без него берётся активная вкладка под управлением.

## Что проверено (selftest.ps1)

`powershell -ExecutionPolicy Bypass -File selftest.ps1` — создаёт вкладку с
тестовой страницей и проверяет: ввод текста, двойной клик (выделяет слово),
тройной клик (строку), выделение протяжкой, копирование в системный буфер,
вставку из буфера и доверенность событий `copy`/`paste`.

Отдельно проверено на портале Ivanti: клик по шестерёнке в шапке открывает
`/AdminUI/DefaultEx.aspx` (Ivanti Service Manager Configuration Interface).

## Грабли

* **Крупные ответы приходят фрагментированными.** Расширение режет большие
  сообщения (скриншоты) на несколько WebSocket-кадров, поэтому читать нужно до
  кадра с `FIN=1` (`ws_read_message`).
* **Ctrl+C / Ctrl+V сами по себе не работают.** Chromium не превращает
  внедрённые через отладчик нажатия в команды правки: `keydown` до страницы
  доходит, а текст в буфер не попадает. Работает только явный параметр
  `commands` у `Input.dispatchKeyEvent` — за это отвечает `/edit`.
* **Кириллица и «капризные» поля.** `/type` даёт событие `input`, но не
  посимвольные `keydown/keypress`. Если поле не реагирует (частая история у
  Ext JS), набирайте по одному символу через `/key`.
* **Порт в расширении без фолбэка** — см. выше.
