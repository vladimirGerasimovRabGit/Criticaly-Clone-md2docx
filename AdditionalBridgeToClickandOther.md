# AdditionalBridgeToClickandOther

Памятка о том, как в MonkeyCode вернули возможность кликать мышью по страницам
в браузере, что именно для этого дорабатывалось и как поднять то же самое в
будущих версиях — за две минуты и без повторного расследования.

Дата работ: 23–24.09.2026. Приложение: `monkeycode-desktop.exe` сборки
**26091601.0.0**. Браузер: Edge 153, расширение MonkeyCode 0.1.0.

---

## 1. Итог в двух абзацах

В сборке `26091601.0.0` инструменты браузера нерабочие: `browser_snapshot`
падает с ошибкой разбора, поэтому ссылки на элементы не регистрируются и
`browser_click` / `browser_type` / `browser_select_option` отвечают
`尚无元素快照` на любой странице. Это баг самого приложения, а не расширения и
не конкретной страницы; установщик `MonkeyCode_latest_x64-setup.exe` приносит ту
же версию, то есть обновляться некуда.

Обход: расширение MonkeyCode — это тонкий релей над `chrome.debugger`, который
просто выполняет приходящие CDP-команды, а в его настройках можно указать любой
порт. Мы поставили «локальным агентом» свой скрипт `tools/mc-bridge/bridge.py`:
расширение переключили на порт 8791, и все браузерные операции пошли через
обычный CDP — настоящие клики мышью, выделение, ввод, копирование, вставка,
скриншоты, управление вкладками. Живой браузер и ваш профиль при этом не
затрагиваются: работает та же вкладка с той же авторизацией.

## 2. Диагноз: почему кликов не было

### 2.1. Что именно ломается

`browser_snapshot` возвращал:

```
[MCP tool error] 快照元数据解析失败: invalid type: string
"[{\"tag\": \"button\", \"text\": \"\"}, ...]", expected a sequence at line 1 column 4048
```

Разбор:

* Скрипт обхода страницы зашит внутрь `monkeycode-desktop.exe` (не файл на
  диске) и заканчивается так:
  ```js
  return JSON.stringify({ url, title, scrollY, winH, docH,
                          crossOriginIframes, truncated, gen, items });
  ```
  то есть отдаёт **строку**, внутри которой `items` — массив.
* Рядом в бинарнике лежат свои структуры `SnapshotMeta` / `SnapItem` и текст
  ошибки `快照元数据解析失败: `. Парсер получает строку там, где ждёт массив,
  разбор не удаётся, и — главное — **таблица ссылок на элементы не создаётся**.
* Следствие: `browser_click` отвечает `尚无元素快照,请先调用 browser_snapshot`
  всегда, потому что таблица строится из того же разбора. Кликнуть нельзя ни по
  чему.

### 2.2. Почему расширение не виновато

* `background.js` расширения — только релей: принял кадр, вызвал
  `chrome.debugger.sendCommand`, вернул результат. Разметку он не строит.
* Загруженная в Edge копия **байт-в-байт** совпадает с поставочной: путь
  `%LOCALAPPDATA%\MonkeyCode\browser-extension`, версия 0.1.0, SHA-256
  `background.js` = `9F6AF3E2…D03CB4` у обеих копий.
* Поэтому «переустановить/обновить расширение» — тупик; проблема в парсере
  приложения.

## 3. Как устроено решение

### 3.1. Протокол расширения (снят из `assets/core-mwIdV_Nm.js` и `background.js`)

* Расширение **само** соединяется по WebSocket с «агентом»:
  `ws://127.0.0.1:<порт>/ext`.
* Порт берётся из `chrome.storage.local.port`; **если порт задан — список
  состоит только из него**, фолбэка на 7440–7449 нет. Если порт не задан —
  сканируются 7440…7449 по порядку.
* После открытия сокета расширение шлёт:
  ```json
  {"event":"hello","auth":{"token":"…"},"ext":{"id":"…","version":"0.1.0"},"browser":"…","proto":1}
  ```
  и ждёт ответ `{"event":"hello.ok","token":"…"}` (таймаут 3 с).
  Полученный `token` сохраняется и используется в следующий раз.
* Дальше — кадры-операции от агента: `{"id":N,"op":"…",…}` и ответы
  `{"id":N,"result":…}` либо `{"id":N,"error":{code,message}}`.
  События от расширения: `cdp`, `tab.updated`, `tab.removed`, `detached`,
  `handoff`.
* Операции: `cdp`, `tabs.create` (параметры — во вложенном `params`, в частности
  `params.url`), `tabs.list`, `tabs.activate`, `tabs.close`, `attach`, `detach`,
  `frames.list`, `ping`.
* **Guard**: для `cdp`, `attach`, `tabs.close`, `frames.list` вкладка обязана
  быть в `controlledTabs` (хранится в `chrome.storage.session`). Вкладка попадает
  туда, когда её выдал пользователь (handoff) или когда её создал сам агент.
  Остальные операции доступны свободно. При отказе — `not_controlled`.
* `tabs.create` в отсутствие URL открывает `about:blank` и создаёт/использует
  «окно агента».

### 3.2. Наш мост

`tools/mc-bridge/bridge.py` — один процесс Python, слушает `127.0.0.1:8791`:

```
я (PowerShell/Invoke-RestMethod)
      │ HTTP
      ▼
bridge.py  ── WebSocket /ext ──►  расширение  ── chrome.debugger ──►  вкладка Edge
      ▲                                                                    │
      └──────────────── результат CDP ◄────────────────────────────────────┘
```

* `/ext` — WS-сервер: принимает handshake, отвечает `hello.ok`, причём в ответе
  возвращает **тот же токен, который расширение предъявило** в `hello` (то есть
  выданный приложением) — поэтому возврат на порт 7440 не требует перепаривания.
  Если `hello` пришёл без токена, генерируется новый; жёстко задать токен можно
  переменной окружения `MCB_TOKEN`. Дальше мост принимает кадры операций и
  раздаёт их разным HTTP-запросам по `id` с ожиданием ответа.
* Остальные пути — HTTP-API для CDP (список в приложении А).
* Читает кадры фрагментированно, шлёт только с маской-заголовком сервера,
  отвечает на `ping`, переподнимает соединение при обрыве.

«扩展程序选项», либо сразу
`chrome-extension://bhmoekbeakkmhaakojecgmnaomcepboa/src/options/options.html`)

  `https://ermolov.trysaasiteu.com/AdminUI/DefaultEx.aspx`
  («Ivanti Service Manager Configuration Interface»). Скриншот подтвердил:
  страница **SETTINGS** с разделами Configure / Build / Extend и быстрыми
  ссылками.
* Дополнительно проверено, что события настоящие: на страницу повешен слушатель,
  и клик дал
  `pointerdown/mousedown/mouseup/click`, `target = ext-gen365`, `isTrusted: true`.

*Грабля:* первая проверка «открылось ли меню» смотрела только `.x-menu` в DOM
текущей страницы — а шестерёнка открывает **новую вкладку/окно**, которой в DOM

*Побочный эффект:* три клика в диагностике открыли три окна настроек; два
закрыты через `{"op":"tabs.close","tabId":…}`.

### Шаг 3. Починка скриншотов (фрагментация WebSocket)

`/shot` падал с пустым HTTP 500, в логе моста:

```
нечитаемый кадр: Unterminated string starting at: line 1 column 26 (char 25)
```

Причина: **расширение режет крупные ответы (скриншот) на несколько
WebSocket-кадров**, а мост читал только первый кадр и пытался разобрать его как
готовый JSON; продолжения (opcode `0x0`) отбрасывались.

Решение — читать до кадра с `FIN=1`:

```python
def ws_read_frame(sock):          # (fin, opcode, payload)
    b1, b2 = recv_exact(sock, 2)
    fin = bool(b1 & 0x80); opcode = b1 & 0x0F; length = b2 & 0x7F
    ...

def ws_read_message(sock):
    fin, opcode, data = ws_read_frame(sock)
    if opcode >= 0x8:                      # control-кадры не фрагментируются
        return opcode, data
    buf = data
    while not fin:
        fin, _op, chunk = ws_read_frame(sock)
        buf += chunk
    return opcode, buf
```

После этого `Page.captureScreenshot` (`jpeg`, `quality 65`) отдал 131 562 байта
и картинку 1912×901.

* `drag` — `mousePressed`, 12 промежуточных `mouseMoved` с `buttons: 1`,

### Шаг 5. Модификаторы и «настоящие» коды клавиш

Оказалось, что `Ctrl+A/C/V` не работают, хотя `keydown` до страницы доходит.
Промежуточная правка — корректные `code`/`windowsVirtualKeyCode` для букв и цифр
(`KeyA`/65 и т.п.), тип `keyDown` вместо `rawKeyDown` при модификаторах — **не
помогла**.

*Грабля:* для INPUT-поля проверка через `window.getSelection()` бессмысленна —
у полей выделение живёт в `input.selectionStart/End`, `getSelection()` вернёт
пусто.

### Шаг 6. Копирование и вставка через `commands` (ключевая находка)

Диагностика показала: `keydown` с `ctrl=true` до страницы доходит (в логе
`window.__keys`), но `selectAll`/`copy`/`paste` не выполняются — Chromium не
превращает нажатия, внедрённые через отладчик, в команды редактирования.
Работает только явный параметр `commands` у `Input.dispatchKeyEvent`:

| Приём | Результат |
|---|---|
| `keyDown ctrl+a` | выделения нет (`6:6`) |
| `rawKeyDown a modifiers=2 commands=["selectAll"]` | выделено (`0:6`) |
| `keyDown ctrl+c` | буфер не изменился |
| `rawKeyDown c modifiers=2 commands=["copy"]` | в буфере `abcdef`, страница увидела `copy` |
| `keyDown ctrl+v` | поле не изменилось |
| `rawKeyDown v modifiers=2 commands=["paste"]` | поле `abcdefPASTE-B-222`, страница увидела `paste:PASTE-B-222` |

Реализовано: `send_command()` и точки `/edit` со словами
`selectAll | copy | cut | paste | undo | redo`.

## 5. Инструкция: поднять мост в будущей версии (5 минут)

Предусловия: установлен Python 3 (`python --version`), установлено расширение
MonkeyCode в Edge, есть каталог `tools/mc-bridge` (если нет — скопировать
`bridge.py`, `selftest.ps1`, `README.md`).

### 5.1. Сначала проверить, нужен ли мост вообще

В новой сборке приложения баг может быть уже исправлен. Проверка:

1. Открыть любую страницу с кнопками и вызвать инструмент `browser_snapshot`.
2. Если вернулся список элементов — **баг исправлен**, мост не нужен: работайте
   штатными `browser_click` / `browser_type`. Если расширение уже смотрит на
   мост, верните его приложению (см. 5.5).
3. Если снова `快照元数据解析失败` / `expected a sequence` — переходите к 5.2.

### 5.2. Запустить мост

```powershell
$exe = & python -c "import sys; print(sys.executable)"
Start-Process -FilePath $exe -ArgumentList 'C:\Users\Verd-\MonkeyCode\tools\mc-bridge\bridge.py' -WindowStyle Hidden
Start-Sleep -Seconds 2
Invoke-RestMethod -Uri 'http://127.0.0.1:8791/status' | ConvertTo-Json
```

Ожидаемо на этом шаге: `{"connected":false,…}` — расширение ещё на стороне
приложения.

### 5.3. Переключить расширение на мост (два клика руками)

1. Edge → `edge://extensions` → «MonkeyCode 浏览器助手» → «详细信息» →
   «扩展程序选项». Прямая ссылка:
   `chrome-extension://bhmoekbeakkmhaakojecgmnaomcepboa/src/options/options.html`
   (если ID изменился — смотреть `chrome://extensions` или ключ в
   `manifest.json`).
2. `agent 端口` = `8791`, `配对码` = любое слово → «连接并配对».

Сразу после этого `/status` должен показать `"connected": true` —
расширение переподключается за ~3 секунды (у него есть alarm-keepalive каждые
30 секунд, так что и после перезапуска моста оно вернётся само).

### 5.4. Проверить, что всё живо

```powershell

  ForEach-Object { "#{0} controlled={1} active={2} {3}" -f $_.tabId, $_.controlled, $_.active, $_.title }

# 2. полный прогон возможностей
powershell -NoProfile -ExecutionPolicy Bypass -File 'C:\Users\Verd-\MonkeyCode\tools\mc-bridge\selftest.ps1'
```

Если у нужной вкладки `controlled=False` — её надо выдать агенту: в попапе
расширения («交付/认领» текущей вкладки) либо создать вкладку самим агентом
(`tabs.create`), тогда она сразу попадает в `controlledTabs`.

### 5.5. Вернуть как было

Настройки расширения → очистить поле `agent 端口` (пусто = авто-сканирование
7440–7449) → «连接并配对». Токен мост отдаёт тот же, что предъявило расширение
(то есть выданный приложением), поэтому перепаривание не требуется, браузерные
инструменты приложения заработают снова. Мост можно оставить запущенным — он
просто не будет получать клиента.

**Важно:** непустой порт фолбэка не имеет. Если расширение смотрит на 8791, а
мост не запущен, браузерные инструменты приложения останутся нерабочими, пока
поле не очистят. Поэтому при переключении всегда сначала поднимайте мост, потом
меняйте порт.

## 6. Шпаргалка: типовые вызовы

```powershell
$base = 'http://127.0.0.1:8791'
function Post($p, $o) { Invoke-RestMethod -Uri "$base$p" -Method Post -Body ($o | ConvertTo-Json -Compress -Depth 8) `
  -ContentType 'application/json; charset=utf-8' -TimeoutSec 45 }
function Eval($e, $t) { (Post '/eval' @{ expression = $e; tabId = $t }).value }
function Cdp($m, $pr, $t) { (Post '/cdp' @{ method = $m; params = $pr; tabId = $t }).result }

# вкладки
(Post '/op' @{ op = 'tabs.list' }).result
```

## 7. Ограничения и риски (читать перед использованием)

* **Мост не аутентифицирует клиента.** Любой локальный процесс, знающий порт,
  может через `/cdp` и `/eval` читать и менять любые страницы в браузере —
  включая формы с паролями и открытые сессии. Держите его запущенным только
  тогда, когда он нужен, либо осознанно принимайте риск. Слушает он только
  `127.0.0.1`, наружу не торчит.
* **Один клиент у расширения.** Пока расширение смотрит на мост, браузерные
  инструменты приложения мертвы (и `browser_navigate`, и `browser_press_key`, и
  `browser_take_screenshot`).
* **Порт без фолбэка** — см. 5.5.
* **Буфер обмена общий с системой.** Тесты и вставки перезаписывают то, что у
  вас сейчас скопировано.
* **`/type` ≠ посимвольный ввод.** `Input.insertText` даёт событие `input`, но не
  `keydown/keypress`; капризные поля (Ext JS и подобные) стоит набивать по
  одному символу через `/key`.
* **Фрагментация и размер.** Большие ответы приходят несколькими кадрами
  (учтено), но очень большие страницы через `Runtime.evaluate` лучше не тащить
  целиком — снимайте частями.
* **Разметка «на глаз» не проверяется.** Сначала смотрите `/tabs` и DOM,
  и только потом делайте выводы: меню и диалоги часто открываются в новых окнах.

## 11. Приложение Г. Автозапуск моста после перезагрузки

Проверено 24.09.2026, на живой перезагрузке ПК.

### 11.1. Что именно ломается при перезагрузке

* `bridge.py` — обычный процесс, поднимать его некому: после ребута порт 8791
  молчит, пока мост не запустят руками.
* Настройки расширения при этом целы: порт и токен лежат в
  `chrome.storage.local` профиля Edge (`Profile 2`, LevelDB каталога
  `Local Extension Settings\bhmoekbeakkmhaakojecgmnaomcepboa`).
* А вот **код сопряжения теряется**. В `background.js` он кладётся в
  `chrome.storage.session` (`case"pair": chrome.storage.session.set({pairingCode:...})`),
  а session-хранилище очищается при перезапуске браузера. `connect()` читает
  `token` (local) и `pairingCode` (session) и, если **оба пусты**, сразу ставит
  статус `unpaired` — к мосту он в этом состоянии не стучится вообще.
  Симптом: страница настроек расширения пишет «未配对» и красное
  «请先输入配对码».
* Если расширение сопряжено, связь оно держит само: будильник
  `chrome.alarms.create("bridge-keepalive", {periodInMinutes: 0.5})` каждые
  30 секунд зовёт `ensureConnected()`, плюс есть `scheduleRetry()` с растущей
  паузой. Поэтому перезапуск моста расширение переживает молча — проверено:
  мост убит и поднят заново, `connected:true` через ~5 секунд, без единого
  клика.

Итог: **руками остаётся один раз за сессию браузера вписать код сопряжения**
(и выдать вкладку через 交付/认领). Мост поднимается сам.

### 11.2. Как это сделано

`tools/mc-bridge/watchdog.ps1` — сторож (PowerShell 5.1, прав администратора
не требует): раз в 10 секунд смотрит процесс `monkeycode-desktop` и опрашивает
`http://127.0.0.1:8791/status`; если приложение запущено, а порт молчит —
стартует `bridge.py` через `pythonw.exe` (скрыто, без окна консоли).
Мост при этом не гасится: закрытие приложения его не останавливает (решение
пользователя), поэтому сторожу достаточно просто быть запущенным.

Сторож поднимается из автозагрузки ярлыком
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\mc-bridge-watchdog.lnk`:

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\Users\Verd-\MonkeyCode\tools\mc-bridge\watchdog.ps1"
```

Почему сторож, а не «задача по запуску приложения»: у Планировщика нет
триггера «появился процесс» без включённого аудита 4688, а WMI-подписка на
`Win32_ProcessStartTrace` требует прав администратора и тяжелее. Сторож в
автозагрузке решает ту же задачу (мост поднимается по факту старта MonkeyCode)
и прав не требует.

### 11.3. Проверить, что всё живо


Удалить ярлык из автозагрузки и снять процесс сторожа — больше система нигде

## 13. Приложение Е. Виджет остатка токенов и пузырь над обезьяной

Сделано 24.09.2026. Задача: видеть остаток токенов пакета, не открывая
настройки (страница Settings → Account грузится около 11 секунд, всё это время
висит на «Loading sign-in status…», окно мелькает).

### 13.1. Откуда берётся цифра

Приложение ходит за ней на свой API. Те же два запроса можно повторять снаружи,
с cookie приложения:

| запрос | что внутри |
|---|---|
| `GET https://monkeycode-ai.com/api/v1/users/wallet` | `data.daily_token_balance` — остаток токенов (из него «58.0M»), `data.daily_token_limit` — дневной лимит (100 000 000), `data.balance` — кредиты в милли-кредитах (11 267 843 → 11 267) |
| `GET https://monkeycode-ai.com/api/v1/users/subscription` | `data.plan` (`pro`), `data.expires_at`, `enable_credit_consumption` |

Cookie `monkeycode_ai_session` лежит в
`%APPDATA%\com.chaitin.baizhi.monkeycode\monkeycode-cookies.json` — это
JSON-массив, нужен элемент с доменом `monkeycode-ai.com` и полем `value`. Файл
перечитывается перед каждым запросом, поэтому после нового входа в приложение
виджет подхватывает сессию сам, без правок скрипта.

**Не вызывать** `POST /api/v1/users/wallet/checkin` — он начисляет кредиты, то
есть меняет состояние аккаунта. Остальные запросы из памятки — только чтение.

### 13.2. Главная грабля: PowerShell 5.1 молча не отправляет cookie

Проверено на живом аккаунте:

* `Invoke-WebRequest` / `Invoke-RestMethod` с `-Headers @{ Cookie = ... }` —
  cookie не уходит вообще, ответ `401`;
* то же с `-WebSession` — падение с `NullReferenceException`;
* `curl.exe` и Python с тем же cookie — `200` и те же цифры.

Работает только `System.Net.HttpWebRequest` + `CookieContainer`:

```powershell
$req = [System.Net.HttpWebRequest]::Create($url)
$req.CookieContainer = New-Object System.Net.CookieContainer
$req.CookieContainer.Add((New-Object System.Net.Cookie('monkeycode_ai_session', $value, '/', 'monkeycode-ai.com')))
$req.Headers.Add('Accept', 'application/json, text/plain, */*')
$req.Headers.Add('Referer', 'https://monkeycode-ai.com/')
$req.Headers.Add('Origin', 'https://monkeycode-ai.com')
```

### 13.3. Обезьяна: почему нельзя встроиться внутрь

`MonkeyCode 桌宠` — отдельное окно самого приложения, класс
`MonkeyCodeNativePetLayeredWindow`, 116 × 120. Через UI Automation окно отдаёт
**ноль** дочерних элементов: рисование своё, вписаться снаружи некуда. Свою
плашку (например «1 个任务运行中») обезьяна рисует сама, внутри своего окна, над
головой.

Решение: свой маленький пузырь **над обезьяной**, который за ней ездит. Позиция
берётся не через UIA, а через `FindWindow` + `GetWindowRect` по имени класса, раз
в секунду:

```powershell
[DllImport("user32.dll", CharSet = CharSet.Unicode)] static extern IntPtr FindWindow(string cls, string name);
[DllImport("user32.dll")] static extern bool GetWindowRect(IntPtr h, out RECT r);
```

Пузырь 142 × 56 показывает план, «58.0M / 100.0M», полоску остатка и строку
«кредиты · время». Клик по пузырю — обновить сейчас; перетаскивание мышью
открепляет его и превращает в обычную карточку 302 × 118 (вернуть — галочкой
«Прикрепить к обезьяне» в контекстном меню, там же «Обновить сейчас» и «Выход»).
Если окна обезьяны на экране нет, пузырь просто прячется. Данные обновляются раз
в 5 минут, при ошибке запроса — раз в минуту.

### 13.4. Сторожок: виджет живёт вместе с обезьяной

`tools/mc-usage/watchdog.ps1` (PowerShell 5.1, прав администратора не требует)
раз в 20 секунд смотрит: приложение `monkeycode-desktop` запущено, а виджета
нет — поднимает `widget.ps1` скрыто; приложение закрыто — гасит виджет. Сам
сторожок стартует из автозагрузки ярлыком
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\mc-usage-watchdog.lnk`:

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\Users\Verd-\MonkeyCode\tools\mc-usage\watchdog.ps1"
```

Пока делался сторожок, полдня ушло на грабли PowerShell 5.1 — все три ломают
молча, без единой ошибки на экране:

1. **Переменные регистронезависимы.** `$Widget` (путь к скрипту) и `$widget`
   (список процессов) — одна и та же переменная. Список затирал путь, виджет
   запускался с пустым `-File` и умирал на старте; в его `widget.err.log`
   оставалось «Не удалось обработать -File "": Путь имеет недопустимую форму».
   Лечится говорящими именами: `$WidgetFile` и `$widgets`.
2. **`Get-Process` на несуществующее имя пишет в поток ошибок.** У процесса,
   поднятого из автозагрузки (или через WMI), этот поток никуда не ведёт, и
   сторожок от этой записи молча умирает — ровно тогда, когда приложение
   закрыто и виджет надо погасить. Приложение надо искать через
   `Get-CimInstance Win32_Process -Filter "Name='monkeycode-desktop.exe'"`.
3. **Массив из функции разворачивается.** Функция, нашедшая ровно один виджет,
   возвращает не массив, а один объект: `.Count` пуст, и оба сравнения —
   `-gt 0` и `-eq 0` — ложны. Симптомы с двух сторон: виджет не гаснул за
   закрытым приложением и не поднимался, когда его не было. Лечится обёрткой на
   месте вызова — `$widgets = @(Get-WidgetProcesses)`. Оборачивать внутри функции
   через запятую нельзя: получится вложенный массив, и у элементов не будет
   `ProcessId`.

Мелочи оттуда же: `-ArgumentList` массивом падает на пути с дефисом — передавать
строкой с кавычками; файлы скриптов сохранять в UTF-8 **с BOM**, иначе 5.1
калечит кириллицу; долгоживущим дочерним процессам обязательно перенаправлять
вывод в файлы (`-RedirectStandardOutput` / `-RedirectStandardError`), иначе их
ошибки пропадают бесследно.
